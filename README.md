# Carl Sandburg Swim Guard

Swim lesson management for Carl Sandburg staff. The app uses React + Vite in the browser and Supabase Auth, Postgres, Row Level Security, and Realtime for the backend.

## Local setup

1. Copy `.env.example` to `.env`.
2. Set `VITE_SUPABASE_URL` to the Supabase project URL.
3. Set `VITE_SUPABASE_ANON_KEY` to the Supabase publishable/anon key.
4. Run `npm install` and `npm run dev`.

Never put a Supabase service-role key in this project. The browser uses only the publishable/anon key; authorization is enforced by Supabase Auth and RLS.

## Available commands

- `npm run dev` starts the local development server.
- `npm run lint` checks the JavaScript source.
- `npm test` runs the automated unit tests.
- `npm run build` creates the production bundle.
- `npm run preview` previews the production bundle locally.

## Supabase setup

The deployed schema is documented in `src/supabase/schema.sql`. Before testing a staff account, confirm that its Auth user ID matches `public.users.id` and that `public.users.role` is either `head_guard` or `instructor`.

Run the SQL in `src/supabase/migrations/20260825_delete_student.sql` in Supabase SQL Editor. It adds the secure head-guard deletion function and tightens instructor visibility to assigned students and notes.

Run `src/supabase/migrations/20260825_enable_notifications_realtime.sql` once as well so new alerts can arrive live.

Run `src/supabase/migrations/20260825_staff_deactivation.sql` to enable reversible staff access. Deactivation preserves historical records, prevents self-deactivation, and removes inactive staff from assignment and API access.

Run `src/supabase/migrations/20260826_instructor_privacy.sql` to provide the instructor-safe roster view. Instructors can review assigned students and attendance; head guards manage permanent student information such as Special information.

Run `src/supabase/migrations/20260911_invite_signup_sync.sql` to enable invite redemption and Auth-to-public-user synchronization.

Run `src/supabase/migrations/20260911_invite_signup_fix.sql` after it. This allows anonymous invite validation during signup and redeems the code only when the Auth account is created.

Run `src/supabase/migrations/20260911_invite_notification_cleanup.sql` to make invite removal and alert clearing persist securely.

Email delivery is optional. The head guard can copy the generated code from the Invite staff panel and send it manually. The app creates and validates the code directly through Supabase without requiring an Edge Function or email provider.

Instructor account deletion requires deploying `supabase/functions/delete-account/index.ts`. It uses the Supabase service role only on the server to remove the Auth user, profile, assignments, and access so the email can be invited again.

Invites are generated by head guards and delivered manually. New staff use the invite code in the app's account-creation form. Supabase Auth email confirmation may need to be enabled or disabled according to the club's setup.

For local development, add the local URL to Supabase Auth redirect URLs if email confirmation is enabled:

```text
http://127.0.0.1:5173/
http://localhost:5173/
```

## Vercel deployment

1. Push the repository to GitHub.
2. Import the repository into Vercel.
3. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` as Vercel environment variables for Preview and Production.
4. Deploy. `vercel.json` supplies the Vite build and output settings.
5. Add the deployed Vercel URL to Supabase Auth redirect URLs.
6. Set the Supabase Auth Site URL to the deployed Vercel URL. The app uses the current site origin for confirmation links, so production links return to Vercel and local development links return locally.

The app includes a manifest and service worker for installability. Offline mode preserves the app shell, while authentication and live Supabase data require a network connection.
